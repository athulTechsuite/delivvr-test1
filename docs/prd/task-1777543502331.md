# Add role-based access control (RBAC) to delivery management app

## Summary
This feature introduces a three-role RBAC system — `customer`, `driver`, and `admin` — to the Express/SQLite delivery management application. A `role` column is added to the `users` table, embedded in JWT payloads at login time, and enforced by a new `requireRole` middleware factory. Without RBAC, any authenticated user can access every route; this change introduces proper privilege separation so drivers can update order statuses and admins can manage user roles via a dedicated panel — functionality required for the app to operate as a real multi-party delivery platform. The key design constraint is that `models/User.js` opens `database.db` while `app.js` and `models/Order.js` use `database.sqlite` — admin routes must use the shared `db` instance from `app.js`, not `User.findAll()` / `User.updateById()` from the model.

## Objective
- Enforce role-based access on every protected route so that callers holding the wrong role receive HTTP 403 `{ "error": "Forbidden" }` and never reach the handler
- Give drivers and admins an exclusive `PATCH /orders/:id/status` endpoint so order lifecycle transitions (`pending → in_transit → delivered`, etc.) can only be triggered by authorised parties
- Give admins a self-service user-management panel (`GET /admin/users`, `POST /admin/users/:id/role`) so role assignment does not require direct DB access after initial bootstrap

## Mandatory Codebase Review
- **`app.js`** — read fully before touching anything: inline `db.serialize()` block owns the DDL, inline `authenticateToken` is the auth pattern to mirror, and `jwt.sign({ id, email }, ...)` at line 285 is the exact spot to inject `role`
- **`middleware/auth.js`** — pattern reference for the `requireRole` factory; note that this file is NOT imported by `app.js` (orphaned dead code) — use it only as a structural template, do not import it from admin routes
- **`models/User.js`** — provides `findAll()` and `updateById()` but connects to `database.db` (line 6) instead of `database.sqlite`; admin routes must use the `db` instance from `app.js` directly via inline queries to avoid cross-file DB split
- **`models/Order.js`** — exposes `ORDER_STATUS` constants (`pending`, `in_transit`, `out_for_delivery`, `delivered`, `cancelled`) and `findById(id)` — use these for the status-update endpoint
- **`config/database.js`** — exports `{ db }` connected to `database.sqlite`; a future consolidation could import this, but it is out of scope here
- **`views/orders-list.ejs`** — canonical EJS layout: MD CSS classes, Bootstrap Icons CDN, nav structure, EJS `forEach` pattern — `admin-users.ejs` must follow the same conventions

## Business Logic

### Role Hierarchy
- Rule: Three valid role values exist: `'customer'`, `'driver'`, `'admin'` — stored as `TEXT NOT NULL DEFAULT 'customer'` in the `users` table; any other value is rejected at the API boundary with HTTP 400
- Rule: New users automatically receive the `customer` role via the DB column default — no change to the `POST /signup` handler is required
- Rule: The first admin user must be bootstrapped by running `UPDATE users SET role = 'admin' WHERE email = '<addr>';` directly in SQLite, or by an `ADMIN_EMAIL` env-driven seed block added to `db.serialize()` in `app.js`
- Rule: All role-access violations return exactly `{ "error": "Forbidden" }` with HTTP 403 — no redirect, no 401

### JWT Role Claims
- Rule: At login, `jwt.sign()` payload must be `{ id: user.id, email: user.email, role: user.role }` so `req.user.role` is available to `requireRole` on every subsequent request
- Rule: Existing JWTs issued before this change lack a `role` claim; `requireRole` must treat a missing/undefined `role` as `'customer'` using `req.user.role || 'customer'` to prevent a breaking 500 during the transition window

### Order Status Transition
- Rule: Only `driver` and `admin` roles may call `PATCH /orders/:id/status`; request body must contain `{ status: string }` where `status` is one of the five `ORDER_STATUS` values from `models/Order.js`; any other value returns HTTP 400 `{ "error": "Invalid status" }`
- Rule: If the target order does not exist, return HTTP 404 `{ "error": "Order not found" }`; ownership is not checked on this endpoint (drivers can update any order's status)

### Admin User Management
- Rule: Only `admin` role may call `GET /admin/users` or `POST /admin/users/:id/role`
- Rule: `POST /admin/users/:id/role` validates that the submitted `role` value is one of `['customer', 'driver', 'admin']`; invalid values return HTTP 400 `{ "error": "Invalid role" }`
- Rule: On success, `POST /admin/users/:id/role` redirects to `GET /admin/users` (HTTP 302) — consistent with form-POST-redirect patterns used throughout `app.js`

### 3. RBAC Middleware
**Files:** `middleware/rbac.js` *(new file)*
**What:** Export a `requireRole(...roles)` factory that reads `req.user.role` (populated by `authenticateToken`) and returns HTTP 403 JSON on mismatch. Mirrors the structure of `middleware/auth.js`.

**Before (key section):**
```javascript
// middleware/auth.js — structural template (file exists, not used by app.js)
const authenticateToken = (req, res, next) => {
    // ...
    jwt.verify(finalToken, jwtSecret, (err, user) => {
        if (err) {
            return res.redirect('/login');
        }
        req.user = user;
        next();
    });
};
module.exports = { authenticateToken, redirectIfAuthenticated };
```

**After:**
```javascript
// middleware/rbac.js — new file
/**
 * requireRole(...roles) — factory returning Express middleware that enforces
 * role-based access. Must be used AFTER authenticateToken so req.user is set.
 *
 * Usage: router.patch('/orders/:id/status', authenticateToken, requireRole('driver', 'admin'), handler)
 */
const requireRole = (...roles) => (req, res, next) => {
    const userRole = (req.user && req.user.role) || 'customer';
    if (!roles.includes(userRole)) {
        return res.status(403).json({ error: 'Forbidden' });
    }
    next();
};

module.exports = { requireRole };
```

**Before (key section):**


**After:**
```javascript
// Add at top of app.js with other requires:
const { requireRole } = require('./middleware/rbac');

// ...existing routes...

// PATCH /orders/:id/status — driver and admin only
app.patch('/orders/:id/status', authenticateToken, requireRole('driver', 'admin'), async (req, res) => {
    const rawId = req.params.id;
    const parsedId = Number.parseInt(rawId, 10);
    if (!Number.isInteger(parsedId) || parsedId <= 0 || String(parsedId) !== String(rawId).trim()) {
        return res.status(404).json({ error: 'Order not found' });
    }

    const { status } = req.body;
    const validStatuses = Object.values(Order.STATUS);
    if (!status || !validStatuses.includes(status)) {
        return res.status(400).json({ error: 'Invalid status' });
    }

    try {
        const order = await Order.findById(parsedId);
        if (!order) {
            return res.status(404).json({ error: 'Order not found' });
        }
        await new Promise((resolve, reject) => {
            db.run('UPDATE orders SET status = ? WHERE id = ?', [status, parsedId], function(err) {
                if (err) return reject(err);
                resolve();
            });
        });
        const updated = await Order.findById(parsedId);
        return res.status(200).json(updated);
    } catch (err) {
        console.error('Error updating order status:', err);
        return res.status(500).json({ error: 'Internal server error' });
    }
});

app.post('/logout', (req, res) => {
    res.clearCookie('token');
    res.redirect('/');
});
```

**After:**

```javascript
// routes/admin.js — new file
const express = require('express');

/**
 * createAdminRouter(db, authenticateToken, requireRole)
 * Receives the shared sqlite3 db instance from app.js so it operates on
 * database.sqlite, not the separate database.db used by models/User.js.
 */
function createAdminRouter(db, authenticateToken, requireRole) {
    const router = express.Router();
    const VALID_ROLES = ['customer', 'driver', 'admin'];

    // GET /admin/users — list all users with roles
    router.get('/users', authenticateToken, requireRole('admin'), (req, res) => {
        db.all('SELECT id, name, email, role, created_at FROM users ORDER BY id ASC', [], (err, users) => {
            if (err) {
                console.error('Error fetching users:', err);
                return res.status(500).json({ error: 'Internal server error' });
            }
            res.render('admin-users', { user: req.user, users: users || [] });
        });
    });

    // POST /admin/users/:id/role — update a user's role
    router.post('/users/:id/role', authenticateToken, requireRole('admin'), (req, res) => {
        const rawId = req.params.id;
        const parsedId = Number.parseInt(rawId, 10);
        if (!Number.isInteger(parsedId) || parsedId <= 0 || String(parsedId) !== String(rawId).trim()) {
            return res.status(400).json({ error: 'Invalid user id' });
        }

        const { role } = req.body;
        if (!role || !VALID_ROLES.includes(role)) {
            return res.status(400).json({ error: 'Invalid role' });
        }

        db.run('UPDATE users SET role = ? WHERE id = ?', [role, parsedId], function(err) {
            if (err) {
                console.error('Error updating user role:', err);
                return res.status(500).json({ error: 'Internal server error' });
            }
            if (this.changes === 0) {
                return res.status(404).json({ error: 'User not found' });
            }
            res.redirect('/admin/users');
        });
    });

    return router;
}

module.exports = { createAdminRouter };

// ——— app.js additions ———
// At top, after requireRole import:
const { createAdminRouter } = require('./routes/admin');
const adminRouter = createAdminRouter(db, authenticateToken, requireRole);
app.use('/admin', adminRouter);

// Error handling middleware (unchanged, must remain last):
app.use((req, res) => {
    res.status(404).render('404');
});
```

## Acceptance Criteria
- [ ] `users` table DDL in `app.js` includes `role TEXT NOT NULL DEFAULT 'customer'` for fresh database installs
- [ ] An `ALTER TABLE users ADD COLUMN role TEXT NOT NULL DEFAULT 'customer'` statement runs in `db.serialize()` with error-ignore callback for existing databases; the callback suppresses only `duplicate column name` errors, logging all others
- [ ] After login, decoding the returned JWT cookie reveals `{ id, email, role }` — `role` is a non-null string matching the user's DB value
- [ ] `middleware/rbac.js` exports a `requireRole(...roles)` function; when `req.user.role` is not in `roles`, it returns HTTP 403 `{ "error": "Forbidden" }` and does not call `next()`
- [ ] When `req.user.role` is `undefined` or missing (legacy JWT), `requireRole` treats it as `'customer'`
- [ ] `PATCH /orders/:id/status` with a `customer` JWT returns HTTP 403 `{ "error": "Forbidden" }`
- [ ] `PATCH /orders/:id/status` with a `driver` JWT and valid `{ status: 'in_transit' }` returns HTTP 200 with the updated order JSON
- [ ] `PATCH /orders/:id/status` with an invalid status value returns HTTP 400 `{ "error": "Invalid status" }`
- [ ] `PATCH /orders/:id/status` for a non-existent order id returns HTTP 404 `{ "error": "Order not found" }`
- [ ] `GET /admin/users` with a `driver` JWT returns HTTP 403 `{ "error": "Forbidden" }`
- [ ] `GET /admin/users` with an `admin` JWT returns HTTP 200 and renders `admin-users.ejs` listing all users with their current roles
- [ ] `POST /admin/users/:id/role` with `{ role: 'driver' }` and an `admin` JWT updates the target user's role in `database.sqlite` and redirects to `/admin/users` (HTTP 302)
- [ ] `POST /admin/users/:id/role` with `{ role: 'superuser' }` returns HTTP 400 `{ "error": "Invalid role" }`
- [ ] Admin routes query `database.sqlite` (the `db` instance from `app.js`), not `database.db` (the instance in `models/User.js`)
- [ ] New user signups receive `role: 'customer'` in the DB without any change to the `POST /signup` handler

## Test Cases

### Functional (TC-F-XXX)
- **TC-F-001** Login includes role claim: POST `/login` with valid credentials for a user with `role = 'driver'` in the DB → decode the `token` cookie → JWT payload contains `{ id, email, role: 'driver' }`
- **TC-F-002** Driver updates order status: Create an order, set a `driver` JWT cookie, PATCH `/orders/1/status` with body `{ "status": "in_transit" }` → response is HTTP 200 with JSON `{ ..., status: 'in_transit' }`
- **TC-F-003** Admin updates order status: Same as TC-F-002 but with an `admin` JWT → HTTP 200 with updated order JSON
- **TC-F-004** Admin lists users: GET `/admin/users` with `admin` JWT cookie → HTTP 200, rendered HTML contains a `<table>` with at least one row per user including name, email, role columns
- **TC-F-005** Admin changes user role: POST `/admin/users/2/role` with body `{ role: 'driver' }` and `admin` JWT → HTTP 302 redirect to `/admin/users`; subsequent `db.get('SELECT role FROM users WHERE id=2')` returns `'driver'`
- **TC-F-006** Customer creates order (unchanged): POST `/orders` with `customer` JWT and valid payload → HTTP 302 redirect to `/orders`; order row exists in DB

### Edge Cases (TC-E-XXX)
- **TC-E-001** Customer blocked from status update: Set `customer` JWT cookie, PATCH `/orders/1/status` with `{ "status": "delivered" }` → HTTP 403 `{ "error": "Forbidden" }`; order status unchanged in DB
- **TC-E-002** Driver blocked from admin panel: Set `driver` JWT cookie, GET `/admin/users` → HTTP 403 `{ "error": "Forbidden" }`
- **TC-E-003** Legacy JWT without role claim: Manually sign a JWT `{ id: 1, email: 'x@y.com' }` (no `role`), use as cookie, hit `PATCH /orders/1/status` (requires `driver`/`admin`) → HTTP 403 `{ "error": "Forbidden" }` — not a 500 crash
- **TC-E-004** PATCH non-existent order: `driver` JWT, PATCH `/orders/99999/status` → HTTP 404 `{ "error": "Order not found" }`
- **TC-E-005** Invalid status value: `driver` JWT, PATCH `/orders/1/status` with `{ "status": "flying" }` → HTTP 400 `{ "error": "Invalid status" }`
- **TC-E-006** Invalid role on POST: `admin` JWT, POST `/admin/users/1/role` with `{ role: 'superuser' }` → HTTP 400 `{ "error": "Invalid role" }`
- **TC-E-007** ALTER TABLE idempotency: Run the server twice against the same `database.sqlite` file → second boot does not crash; the `duplicate column name` error is silently swallowed

### Regression (TC-R-XXX)
- **TC-R-001** Existing login flow unchanged: POST `/login` with valid credentials still returns a `Set-Cookie: token=...` header and redirects to `/dashboard` with HTTP 302
- **TC-R-002** Order creation unchanged: Authenticated customer can POST `/orders`, GET `/orders`, GET `/orders/:id` with no 403 regressions
- **TC-R-003** Unauthenticated access still redirects: GET `/dashboard` without a cookie still returns HTTP 302 to `/login` (not a 403)
- **TC-R-004** Health endpoint unaffected: GET `/health` returns HTTP 200 `{ status: 'ok', ... }` with no auth required
- **TC-R-005** Signup assigns customer role: POST `/signup` with new credentials → user row in DB has `role = 'customer'`

## Risk and Deployment

**Risk Level:** MEDIUM

**Deployment Order:**
1. Deploy `app.js` with the updated DDL (`role` column in `CREATE TABLE`) and the `ALTER TABLE` migration guard — the server will add the column to the live DB on first boot
2. Deploy `middleware/rbac.js` — no routes use it yet so there is zero breakage
3. Deploy updated JWT `sign()` call in the `/login` route — new tokens will carry `role`; old tokens still work because `requireRole` defaults missing `role` to `'customer'`
4. Deploy `routes/admin.js` and `views/admin-users.ejs`
5. Mount admin router in `app.js` and add `PATCH /orders/:id/status`

**Rollback Plan:**
- Revert `app.js` to the previous commit (removes all new routes and DDL); the `role` column remains in the DB but is inert
- Delete `middleware/rbac.js`, `routes/admin.js`, `views/admin-users.ejs`
- If the `role` column must be removed: SQLite does not support `DROP COLUMN` before v3.35; on older SQLite, recreate the table without the column via the rename-create-copy-drop pattern

**Key Risks:**
- **Dual DB file split** (`database.db` in `models/User.js` vs `database.sqlite` in `app.js`): admin routes must use the app-level `db` instance; any import of `models/User.js` in admin routes would silently query the wrong file — mitigation: pass `db` explicitly via `createAdminRouter(db, ...)` factory pattern
- **Legacy JWT transition**: tokens issued before the `role` claim is added will lack `req.user.role`; mitigation: `requireRole` defaults to `'customer'` with `req.user.role || 'customer'`
- **First-admin bootstrap gap**: there is no self-service way to become admin after deploy; mitigation: document the one-time `UPDATE users SET role = 'admin' WHERE email = ?` SQL, or add an `ADMIN_EMAIL` env-driven seed block in `db.serialize()`
- **SQLite `ALTER TABLE` on older versions**: `DEFAULT` expressions in `ADD COLUMN` require SQLite ≥ 3.26 (2018); the `DEFAULT 'customer'` literal is safe on all modern SQLite versions bundled with Node.js `sqlite3`
