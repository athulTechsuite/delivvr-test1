# PRD: Delivvr UI Redesign & Profile Page Enhancement

**Ticket ID:** local-1776927645983
**Date:** 2026-04-23
**Status:** Draft
**Author:** Ticket Writer Agent

---

## Problem Statement

The Delivvr web application currently presents a generic "Express Auth App" identity with a plain blue Material Design color palette and incomplete CSS class definitions that cause visual breakage across multiple pages. The UI does not reflect the Delivvr brand, lacks the visual appeal expected of a modern delivery application, and the profile page is minimal — offering no avatar, no editable fields, and poor visual hierarchy. Users landing on any page of the app encounter a disconnected experience that neither builds brand trust nor communicates the delivery-focused nature of the product.

Specific problems to address:

1. All pages carry the wrong brand name ("Express Auth App" instead of "Delivvr").
2. The color palette is a generic blue — no delivery-themed identity (bold orange/teal is the target).
3. Several CSS classes referenced in EJS templates (`md-profile-item`, `md-card-body`, `md-button-group`, `md-profile-error`, `md-tech-grid`, `md-tech-item`, `md-chip`, `md-section-cta`, etc.) are undefined, causing layout and visual breakage.
4. The home page hero section uses generic copy and no delivery-relevant imagery or icons.
5. Login and Signup pages lack a branded header/logo and use outdated card and input styles.
6. The dashboard lacks visual stat cards and a delivery-focused color scheme.
7. The profile page is bare — no user avatar/initials, no card-based layout, no clear navigation back to the dashboard, and no editable field UX.

- [ ] All CSS classes referenced in EJS templates (`md-profile-item`, `md-card-body`, `md-button-group`, `md-profile-error`, `md-tech-grid`, `md-tech-item`, `md-chip`, `md-section-cta`) are defined in `/public/css/style.css` with appropriate styles and produce no visible layout breakage.
- [ ] The home page (`views/index.ejs`) hero section displays Delivvr-specific headline copy, at least one delivery-related Bootstrap Icon (e.g. `bi-truck`, `bi-box-seam`), and a clear CTA button leading to signup or dashboard.
- [ ] The login page (`views/login.ejs`) displays the Delivvr brand name/logo at the top of the form card, uses the updated color palette on the submit button, and the input fields have visible focus states using the new primary color.
- [ ] The signup page (`views/signup.ejs`) mirrors the login page improvements — branded card header, updated palette, modern input field styling.
- [ ] The dashboard page (`views/dashboard.ejs`) displays stat information inside visually distinct cards that use the new palette, includes a welcome banner with the user's name, and uses delivery-relevant Bootstrap Icons throughout.
- [ ] The profile page (`views/profile.ejs`) displays a circular avatar showing the user's initials (generated from their name), shows name, email, member-since, and account status in a structured card layout, and includes a clearly visible "Back to Dashboard" navigation button.

- [ ] The `views/layout.ejs` sidebar/navbar links for "Profile" and "Dashboard" use the updated Delivvr branding and remain fully functional for authenticated users.

- [ ] No existing backend routes, controllers, or database schema are modified — all changes are confined to EJS view files, `/public/css/style.css`, and `/public/js/` if needed for avatar initials logic.

## Technical Approach

### 1. Rebrand All Pages (views/*.ejs)

Search and replace all occurrences of "Express Auth App" with "Delivvr" across `views/index.ejs`, `views/login.ejs`, `views/signup.ejs`, `views/dashboard.ejs`, `views/profile.ejs`, and `views/layout.ejs`. Update `<title>` tags, navbar brand anchor text, footer copy, and any inline marketing copy.

### 2. Update Color Palette (public/css/style.css)

Modify the `:root` and `.dark-theme` CSS custom property blocks:

- Replace the existing blue primary variable with a bold delivery orange (e.g. `--md-primary: #FF6B00`).
- Add a teal accent variable (e.g. `--md-accent: #00BFA5`).
- Ensure all buttons, active states, focus rings, links, and highlights reference these variables rather than hardcoded hex values.
- Define dark-theme equivalents so the existing theme-toggle continues to work without any JavaScript changes.

### 3. Define Missing CSS Classes (public/css/style.css)

Audit every EJS file for class names not present in `style.css` and add definitions for each. Key classes to add:

- `.md-profile-item` — flex row for a label/value pair on the profile page with bottom border separator.
- `.md-card-body` — padded content area within an `.md-card`.
- `.md-button-group` — flex container for grouping action buttons with gap spacing.
- `.md-profile-error` — styled error message block for profile-related errors (red background, icon, rounded).
- `.md-tech-grid` — CSS grid layout for the tech stack section on the home page.
- `.md-tech-item` — individual tech stack card within the grid.
- `.md-chip` — pill-shaped label/badge component for tags and status indicators.
- `.md-section-cta` — full-width CTA section with background accent, centered content.

### 4. Redesign Home Page (views/index.ejs)

- Update hero headline to delivery-focused copy (e.g. "Fast. Reliable. Delivvr.").
- Add Bootstrap Icons (`bi-truck`, `bi-box-seam`, `bi-geo-alt`) in the hero and features sections.
- Improve the CTA button layout using the new `.md-section-cta` class.
- Replace generic feature descriptions with Delivvr-specific value propositions (real-time tracking, fast delivery, secure handoffs).
- Use the `.md-tech-grid` and `.md-tech-item` classes for the tech stack section.

### 5. Redesign Login & Signup Pages (views/login.ejs, views/signup.ejs)

- Add a branded logo/icon block at the top of each form card using a delivery icon and the "Delivvr" wordmark.
- Apply updated card header background using the primary color variable.
- Add smooth focus transitions on input fields using the new `--md-primary` variable for the focus outline/border.
- Ensure submit buttons use the primary color and show a hover/active state.

### 6. Redesign Dashboard (views/dashboard.ejs)

- Wrap stat figures (e.g. login count, session age) in `.md-card` stat card components with an icon, label, and value — styled with the new palette.
- Add a delivery-themed welcome banner (e.g. "Welcome back, [name] — ready to deliver?") using the primary/accent color.
- Use Bootstrap Icons (`bi-speedometer2`, `bi-clock-history`, `bi-person-check`) for stat cards.
- Apply `.md-chip` for session status and account status indicators.

### 7. Enhance Profile Page (views/profile.ejs)

- Add an avatar circle element at the top of the profile card. The circle renders the user's initials using inline EJS — for a name like "Jane Doe" it shows "JD", for "Alice" it shows "A". Style with the primary color background and white text.
- Restructure the profile info using `.md-profile-item` rows (icon + label + value per row).
- Add a `.md-button-group` at the bottom with a "Back to Dashboard" button linking to `/dashboard`.
- Apply `.md-profile-error` styling to any error flash messages rendered on the page.

### 8. Update Layout / Sidebar (views/layout.ejs)

- Ensure the navbar brand reads "Delivvr" with a delivery icon prefix (`bi-truck`).
- Confirm sidebar navigation links (Profile, Dashboard, Logout) are visible only for authenticated users and correctly styled with the updated palette.
- Verify footer text is updated to reference Delivvr.

## Test Plan

### Manual Visual Regression Tests

1. **Home page** — Load `/` in Chrome at 1280px and 375px. Confirm: Delivvr branding visible in navbar and hero, delivery icon present in hero, CTA button uses orange primary color, tech grid renders without overflow, dark mode toggle switches palette correctly.

2. **Login page** — Load `/login`. Confirm: Delivvr logo/wordmark at top of card, input focus border uses primary color, submit button is orange, no "Express Auth App" text present, dark mode toggle works.

3. **Signup page** — Load `/signup`. Confirm: same criteria as login page.

4. **Dashboard page** — Log in and load `/dashboard`. Confirm: welcome banner shows user name, stat cards render with icons and new palette, chip badges display session/account status, no layout overflow at 375px.

5. **Profile page** — Load `/profile`. Confirm: avatar circle shows correct initials (test with single-name account and two-name account), profile items show icon + label + value rows with separators, "Back to Dashboard" button navigates to `/dashboard`, error state renders with `.md-profile-error` styling if triggered.

6. **Dark mode** — Toggle dark mode on every page. Confirm: all new color variables have dark overrides (no elements revert to hardcoded colors), avatar circle remains legible, chip badges remain readable.

7. **No broken CSS classes** — Open browser DevTools on each page. Confirm: no element has a class that references an undefined CSS rule that causes zero height/width or invisible content.

### Automated / Unit Tests (if test suite exists)

- Verify that existing route tests (`GET /`, `GET /login`, `GET /signup`, `GET /dashboard`, `GET /profile`) continue to return HTTP 200 (or appropriate redirect for unauthenticated routes) — no template rendering errors introduced by EJS changes.
- If a CSS linting step exists, run it to confirm no syntax errors were introduced in `style.css`.

### Accessibility Spot Check

- Confirm avatar circle has `aria-label` with the user's full name.
- Confirm all new icon-only elements (Bootstrap Icons used decoratively) have `aria-hidden="true"`.
- Confirm color contrast ratio for text on primary orange background meets WCAG AA (4.5:1 for normal text).
