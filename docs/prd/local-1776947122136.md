# PRD: Complete UI Overhaul — Dashboard, Login, Signup, and Profile Pages

**Ticket ID:** local-1776947122136
**Date:** 2026-04-23
**Author:** Ticket Writer Agent
**Status:** Draft

---

## Problem Statement

The four primary user-facing pages of the Delivvr application (login, signup, dashboard, and profile) present a broken, inconsistent visual experience that undermines trust in the product. The root cause is a systematic mismatch between class names used in the EJS templates and the class names actually defined in the existing Material Design CSS framework (`/public/css/style.css`).

The CSS file is well-authored (~2000 lines), defining a complete Material Design token system (CSS custom properties, 8dp spacing grid, Roboto typography, elevation shadows, dark-theme overrides, and responsive breakpoints). However, the templates were written against an earlier or assumed API that does not match the CSS. This results in:

1. **Broken button styles** — templates use `md-button-primary`, `md-button-outlined`, `md-button-contained`, `md-button-elevated`, `md-button-large`, `md-button-full-width`, `md-width-full` — none of which are defined. CSS defines `md-button--contained`, `md-button--outlined`, `md-button--text`, `md-button--secondary`, `md-button--large`, `md-button--small`.

2. **Unstyled form controls** — templates use `md-input`, `md-input-container`, `md-input-label`, `md-label`, `md-helper-text`, `md-error-text` — CSS defines `md-form-control`, `md-form-group`, `md-form-label`, `md-form-helper-text`, and `md-form-control--error` modifier.

3. **Invisible alert banners** — templates use `md-alert-error` and `md-alert-success` — CSS defines `md-alert--error` and `md-alert--success` (BEM modifier syntax).

4. **Broken mobile navigation** — signup.ejs, dashboard.ejs, and profile.ejs inline scripts call `navMenu.classList.toggle('md-navbar-nav-open')` — the CSS only defines `.md-navbar-nav.show` (as confirmed in style.css line 621). login.ejs already uses `.show` (correct). The three remaining pages must be brought into alignment.

5. **Missing utility classes used by dashboard.ejs** — `md-display-flex`, `md-bg-primary`, `md-bg-surface`, `md-padding-none`, `md-border-bottom`, `md-list`, `md-list-item`, `md-status-indicator`, `md-border-radius-full`, `md-text-success`, `md-text-info`, `md-margin-right-xs`, `md-margin-right-sm` — none are defined in style.css. Without these, dashboard cards, the activity list, the session status indicator, and layout flex rows render as unstyled blocks.

6. **Duplicate inline `<style>` blocks** — login.ejs and signup.ejs each contain a trailing `<style>` block that re-declares `.md-input:focus` rules. These override style.css with hard-coded values and create specificity conflicts. They must be removed; equivalent rules already belong in style.css.

7. **Inconsistent dark-theme toggle markup** — each page implements the theme toggle widget differently (some use `role="switch"`, others use `role="menuitem"`; some embed a hidden checkbox, others do not). This prevents `theme-toggle.js` from applying a single consistent selector.

The combined effect is that buttons are plain HTML elements, forms have no focus ring or floating labels, alert banners are invisible, the mobile hamburger menu does not open, the dashboard activity list and session card are unstyled plain divs, and the profile page "Back to Dashboard" button uses an inline style instead of the CSS framework.

## Acceptance Criteria

### Buttons
- All primary action buttons across login, signup, dashboard, and profile pages render with the Delivvr orange background (`--md-primary: #FF6B00`), white text, and an 8px border radius, using the class `md-button md-button--contained` (no inline `style` overrides for background/color).
- Outlined/secondary buttons (Quick Actions list, profile card footer) render with a visible border and transparent background using `md-button md-button--outlined`.
- The "Back to Home" button on the dashboard uses `md-button md-button--secondary`.
- No button across any of the four pages relies on an inline `style` attribute to supply its background color, text color, height, border, or border-radius.

### Forms (Login and Signup)
- All `<input>` elements use the class `md-form-control`; all wrapping `<div>` containers use `md-form-group`; all `<label>` elements use `md-form-label`.
- Inputs display the Material Design floating label: label sits inside the input at rest and floats above it on focus or when the field has a value (driven by `.md-form-control:focus + .md-form-label` and `.md-form-control:not(:placeholder-shown) + .md-form-label` selectors already in style.css at lines 970–978).
- Inputs show a visible focus ring (the `md-form-control:focus` rule at line 928 of style.css) with no inline style override overriding it.
- Validation error states use the class `md-form-control--error` on the input element; error text uses the existing `md-form-helper-text` class. No ad-hoc `md-input-error`, `md-error-text`, or `md-helper-text` class names remain in the templates.
- JavaScript event handlers that manipulate form state (focus, blur, error, filled) reference the correct new class names: `md-form-group` for the container and `md-form-control--error` for the error modifier.

### Alert Banners
- Success and error flash messages on login and signup render with the correct background and border colors by using `md-alert md-alert--success` and `md-alert md-alert--error` respectively.
- No page uses `md-alert-success` or `md-alert-error` (non-BEM names) in any EJS template.

### Mobile Navigation
- Tapping the hamburger button on all four pages toggles the class `show` (not `md-navbar-nav-open`) on the `#navbarNav` element.
- The mobile nav opens and closes correctly on screens narrower than the breakpoint defined in style.css (the `.md-navbar-nav.show` rule at line 621).
- The `aria-expanded` attribute is updated correctly on open/close on all four pages.
- Clicking outside the open menu or pressing Escape closes it on all four pages.

### Dashboard Utility Classes
- The following utility classes are added to style.css and apply their documented effects:
  - `md-display-flex` — sets `display: flex`
  - `md-bg-primary` — sets `background-color: var(--md-primary)` and `color: var(--md-text-primary-on-primary)`
  - `md-bg-surface` — sets `background-color: var(--md-surface-2dp)`
  - `md-padding-none` — sets `padding: 0`
  - `md-border-bottom` — sets `border-bottom: 1px solid rgba(0, 0, 0, 0.12)` (with a dark-theme override)
  - `md-border-radius-full` — sets `border-radius: 50%`
  - `md-text-success` — sets `color: var(--md-success)`
  - `md-text-info` — sets `color: var(--md-info)`
  - `md-margin-right-xs` — sets `margin-right: var(--md-spacing-xs)`
  - `md-margin-right-sm` — sets `margin-right: var(--md-spacing-sm)`
  - `md-list` — removes list styling and sets zero padding/margin
  - `md-list-item` — sets `display: flex`, `align-items: center`, and `gap: var(--md-spacing-md)`
  - `md-status-indicator` — sets `width: 10px`, `height: 10px`, `border-radius: 50%`, `display: inline-block`
- The dashboard session card shows the green dot status indicator next to "Active" text.
- The dashboard Recent Activity list renders each entry with an avatar icon, a title, and a subtitle on separate lines.
- The dashboard Profile Information and Quick Actions card headers display the orange primary background (`md-bg-primary`) with white text.

### Inline Style Removal
- The trailing `<style>` block in login.ejs is removed.
- The trailing `<style>` block in signup.ejs is removed.
- Any equivalent `.md-form-control:focus` focus ring rule is consolidated into style.css (already present or added once).
- No inline `style` attribute on buttons, card headers, or form fields remains in any of the four EJS templates. Decorative inline styles on icon font sizes are acceptable only where no CSS utility class exists.

### Dark Theme Toggle Consistency
- All four pages use the same theme toggle HTML structure, matching the pattern used by `theme-toggle.js`: a `<div class="md-theme-toggle">` with `role="switch"` and `aria-checked` attribute, containing a `.md-theme-toggle-track > .md-theme-toggle-thumb` structure with a single icon.
- The theme toggle functions correctly (light/dark switching) on all four pages after markup unification.

### Visual Hierarchy and Typography
- Page headings use the correct typographic scale classes from style.css (e.g. `md-headline-medium`, `md-headline-small`) with no override via inline `style` attributes for `font-size` or `font-weight`.
- Card headers that use `md-bg-primary` display white text using `md-text-primary-on-primary` without an inline `style="color:#fff"` attribute.

### Mobile Layout
- All four pages are visually correct (no overflowing content, no collapsed nav, no stacked full-width buttons that look broken) at a 375px viewport width.
- The grid system (`md-col-*` classes) and the navbar respond correctly at the `md-sm` breakpoint defined in style.css.

## Technical Approach

The fix is a class-name reconciliation: the EJS templates must be updated to use the class names that style.css already defines. No new CSS architecture is needed. The work falls into three layers:

### Layer 1: EJS Template Class Name Fixes (views/)

Each of the four templates must be audited and updated:

**Buttons:** Replace all occurrences of non-BEM button modifiers with their BEM counterparts:
- `md-button-primary` and `md-button-contained` → `md-button--contained`
- `md-button-outlined md-button-primary` → `md-button--outlined`
- `md-button-secondary` or `md-button-contained md-button-secondary` → `md-button--secondary`
- Remove inline `style` attributes on buttons that duplicate what the CSS class provides.

**Forms:** Replace the legacy form class names with the CSS-defined ones:
- `md-input-container` → `md-form-group`
- `md-input` → `md-form-control`
- `md-input-label` and `md-label` → `md-form-label`
- `md-helper-text` → `md-form-helper-text`
- `md-error-text` → `md-form-helper-text md-form-helper-text--error` (or equivalent defined class)
- `md-input-underline` — remove (the underline is part of the `md-form-control` styling in style.css)
- Update the floating label JavaScript handlers in login.ejs and signup.ejs to use `md-form-group`, `md-form-control`, and `md-form-control--error`.

**Alerts:** Replace `md-alert-error` → `md-alert--error` and `md-alert-success` → `md-alert--success`.

**Mobile nav scripts:** In signup.ejs, dashboard.ejs, and profile.ejs, change all `classList.toggle('md-navbar-nav-open')`, `classList.remove('md-navbar-nav-open')`, and `classList.add('md-navbar-nav-open')` calls to use `'show'` instead.

**Dark theme toggle markup:** Standardise to a single pattern across all four pages. Use the structure already working in login.ejs (or whichever page the `theme-toggle.js` was written for), and replicate it exactly in signup.ejs, dashboard.ejs, and profile.ejs.

**Inline `<style>` blocks:** Delete the `<style>` blocks at the bottom of login.ejs and signup.ejs.

### Layer 2: Missing Utility Classes (public/css/style.css)

Add a clearly-labelled "Utility Classes" section to style.css containing the 13 missing utilities listed in the Acceptance Criteria. Each utility should:
- Mirror the naming convention already used in the file (`md-` prefix, BEM-style descriptive suffix).
- Use the existing CSS custom property tokens (e.g. `var(--md-primary)`, `var(--md-spacing-xs)`) rather than hard-coded values.
- Include a dark-theme override block (`.dark-theme .md-border-bottom`, etc.) where the value changes under the dark palette.

Add `md-list` and `md-list-item` component classes (not utilities) alongside the existing card and form component sections.

### Layer 3: No Route or Server Changes Required

All changes are purely front-end (EJS markup and CSS). No Express routes, middleware, or database code needs to change. No new JavaScript files need to be introduced.
