# Modernize Delivvr UI/UX across all EJS views and design system

## Summary
The Delivvr web app currently ships a hand-written Material Design CSS layer (`public/css/style.css`, ~2,287 lines) with inconsistent token usage: `--primary` is set to the brand orange `#FF6B00` while the `--md-primary-50..900` ramp still contains stock Material blues (`#E3F2FD..#0D47A1`), components are duplicated (e.g. `.md-button` and `.md-btn`, `.md-navbar` and `.md-sidebar` both used across views), several pages re-declare `<head>`/navbar markup instead of relying on `views/layout.ejs`, and inline styles leak into `views/dashboard.ejs`. This PRD refactors the design system into a single coherent token set rooted in the Delivvr brand palette, tightens typography and spacing, unifies primitives (buttons, inputs, cards, alerts, badges, tables), polishes every authenticated and unauthenticated view, and verifies dark-mode + responsive parity — without introducing a new framework, build pipeline, JS dependency, or behavioural change.

## Objective
- Replace the residual blue Material ramp (`--md-primary-50..900` lines 13–22, `--md-info: #2196F3` line 69) with a derived orange/teal Delivvr ramp so every `var(--md-primary-*)` reference resolves to brand-coherent colour, and verify WCAG AA contrast (>=4.5:1 for body, >=3:1 for large text) on both light and dark themes for primary, surface, error, success, warning, info pairings.
- Reduce the number of distinct button class names rendered across the 10 EJS views from the current mix (`md-btn`, `md-button`, `md-btn-primary`, `md-button--icon`, `md-navbar-link-button`, `md-nav-button`) to a single canonical primitive (`md-btn` + size/variant modifiers) with deprecation aliases, eliminating duplicate CSS rules and cutting rendered class churn by >=50%.
- Standardise every page on `views/layout.ejs`: remove the duplicated `<!DOCTYPE>`/`<head>`/`<nav class="md-navbar">` blocks currently inlined in `dashboard.ejs` (lines 1–80), `orders-list.ejs` (1–64), `orders-detail.ejs`, `orders-new.ejs`, `profile.ejs`, `index.ejs`, and `404.ejs`, so the Roboto/Bootstrap-Icons CDN links and theme-toggle wiring live in exactly one file.
- Ship a unified type ramp (display, h1–h6, subtitle1/2, body1/2, caption, overline) where every heading on every page uses the same line-height/letter-spacing tokens, and remove all inline `style="font-size:..."` overrides from `dashboard.ejs` (lines 90–98 etc.).
- Audit responsive behaviour at 360px, 768px, and 1280px so the sidebar, navbar, tables (`orders-list.ejs`), and the new-order form (`orders-new.ejs`) reflow without horizontal scroll, and the mobile sidebar overlay closes on Escape and overlay-tap (already wired in `layout.ejs` lines 199–242 — preserve).

## Business Logic
This change is presentational. It must NOT alter authentication, routing, ORM, or any business rule. The "logic" here is design-system invariants.

### Design Tokens
- Rule: `--primary` is `#FF6B00` (Delivvr orange) and `--accent` is `#00BFA5` (Delivvr teal). Both stay constant.
- Rule: `--md-primary-50..900` MUST be a tonal ramp derived from `#FF6B00` (e.g. 50 `#FFF3E8`, 100 `#FFD9B8`, 200 `#FFBE85`, 300 `#FFA352`, 400 `#FF8B26`, 500 `#FF6B00`, 600 `#E55F00`, 700 `#CC5500`, 800 `#A34400`, 900 `#7A3300`). No blue values remain in the ramp.
- Rule: `--md-info` family is replaced with teal-tinted neutrals (e.g. info `#0097A7`, light `#4DD0E1`, dark `#006064`) to align with the `--accent` brand teal.
- Rule: 8dp spacing scale stays canonical (`--md-spacing-xs:4`, `sm:8`, `md:16`, `lg:24`, `xl:32`, `xxl:48`, `xxxl:64`); no new ad-hoc `px` margins introduced in EJS or CSS.
- Rule: Border-radius tokens stay (`sm:4`, `md:8`, `lg:12`, `xl:16`); cards use `md`, buttons use `sm`, modals/overlays use `lg`.

### Typography
- Rule: Type ramp uses Roboto only, weights 300/400/500/700 (already in CDN line 10 of `layout.ejs`).
- Rule: Headings use line-height `1.2` (dense), body uses `1.5` (normal), captions use `1.5`.
- Rule: H1 letter-spacing `-1.5px`, H2 `-0.5px`, H3 `0`, H4 `+0.25px`, H5 `0`, H6 `+0.15px` (already declared lines 247–299; values stay).
- Rule: No inline `style="font-size"`, `style="font-weight"`, or `style="margin"` allowed in any `.ejs` after this PRD lands.

### Components
- Rule: One canonical button class `md-btn` with modifiers `md-btn-primary | md-btn-secondary | md-btn-ghost | md-btn-danger | md-btn-icon | md-btn-sm | md-btn-lg | md-btn-block`. `.md-button` rules become aliases that re-use the same selectors.
- Rule: Status badges have exactly five semantic variants — `md-badge-pending` (warning), `md-badge-in-transit` (info/teal), `md-badge-delivered` (success), `md-badge-cancelled` (error), `md-badge-default` (neutral) — and are used across orders-list, orders-detail, dashboard.
- Rule: All form inputs use `.md-input` with focus-ring `0 0 0 2px rgba(255,107,0,0.25)`, and error state `.md-input-error` (red border + helper text).
- Rule: All cards use `.md-card` + `--md-elevation-2` at rest, `--md-elevation-4` on hover (where interactive); border-radius `--md-border-radius-md`.

### Accessibility
- Rule: All interactive elements maintain a visible focus ring (no `outline:none` without a replacement).
- Rule: Colour contrast >= 4.5:1 for body text, >= 3:1 for large text (>=18.66px or >=14px bold), in BOTH light and dark themes.
- Rule: All existing `aria-*`, `role`, and `sr-only` attributes in `layout.ejs` are preserved; the sidebar Escape-key + overlay-tap close behaviour (lines 230–242) is preserved.

### Responsive
- Rule: Sidebar collapses to mobile drawer below 992px (existing breakpoint at `layout.ejs` line 239 — keep).
- Rule: Tables in `orders-list.ejs` switch to stacked card rows below 768px.
- Rule: Forms use single-column layout below 768px and two-column above where two related fields exist.

## Risk and Deployment
**Risk Level:** MEDIUM (broad surface area but no logic, routing, or data changes)

**Deployment Order:**
1. Land token-ramp updates in `style.css` first (smallest blast radius, fully backward compatible because variable names are unchanged).
2. Land button/badge/card primitive consolidation in `style.css` with alias selectors so old markup still works.
3. Migrate views one at a time in this order: `404.ejs` → `login.ejs` → `signup.ejs` → `profile.ejs` → `orders-list.ejs` → `orders-detail.ejs` → `orders-new.ejs` → `dashboard.ejs` → `index.ejs`.
4. Final pass: remove deprecated alias selectors once all views are migrated and verified.

**Rollback Plan:** This is a presentational change. Revert via `git revert <merge-commit>` — there are no DB migrations, no env-var changes, no third-party config. If only one view regresses, cherry-pick a revert of that single view file.

**Key Risks:**
- Risk: A `var(--md-primary-500)` reference somewhere in CSS expects blue — Mitigation: full-text search for `--md-primary-` usages and visually verify every match in the live app at all breakpoints.
- Risk: A view depends on inlined `<head>` to include a one-off stylesheet — Mitigation: grep all views for `<link rel="stylesheet"` before consolidation; only `style.css` and the two CDN links (Roboto, Bootstrap Icons) should appear.
- Risk: `theme-toggle.js` looks for a specific selector that the refactor removes — Mitigation: read `public/js/theme-toggle.js` end-to-end before changing any class names it references.
- Risk: Dark-mode contrast regression on the new orange tonal ramp — Mitigation: run an automated contrast checker (axe-core or manual ratio computation) against every text/background pairing in both themes.
- Risk: Spec/test suite asserts on a specific class name — Mitigation: keep deprecated class aliases (`.md-button`) in CSS until the test suite is reviewed.

- Internationalisation / RTL support.

**Assumptions:**
- The existing route → view contract in `routes/` is stable and provides the same locals (`title`, `user`, `error`, `success`, `orders`, `order`).

- The two CDN links (Roboto, Bootstrap Icons) remain available and licensed.
- The dev/test environment uses `npm test` and the spec/ directory; no other test runners need to pass.
