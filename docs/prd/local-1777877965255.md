# Add GET /health endpoint to Express app

## Summary
Add a publicly accessible GET /health endpoint to the Express application (app.js) that returns HTTP 200 with a JSON body containing at minimum `{"status": "ok"}`. This endpoint is essential for infrastructure health checks — load balancers, container orchestration systems (Kubernetes liveness/readiness probes), and uptime monitors need a lightweight, unauthenticated route to verify the service process is alive without touching authentication logic or the database. The endpoint must be registered before the existing 404 catch-all middleware so it is reachable, and must not apply the `authenticateToken` or `requireRole` middleware. Jest and supertest must be added as devDependencies and the npm test script must be wired up, because the existing test files use this pattern but the tools are not currently declared in package.json.

## Objective
- Expose GET /health returning HTTP 200 and a JSON body with `status: 'ok'` with no authentication required
- Add jest and supertest as devDependencies and replace the placeholder `npm test` script with a working Jest invocation
- Add a `describe('Health Endpoint')` block in test/app.test.js (or test/routes.test.js) using the supertest pattern, covering success cases and unsupported-method rejection

## Business Logic
### Health Endpoint Registration
- Rule: The route handler `app.get('/health', ...)` must be registered after all other named routes and before the first `app.use(...)` catch-all (the 404 handler at the bottom of app.js). Registering after the catch-all would make the endpoint unreachable.
- Rule: No middleware from `authenticateToken` or `requireRole` is applied. The route is open to all callers — no JWT cookie or Authorization header required.
- Rule: Response HTTP status must be exactly 200. Response body must contain `"status": "ok"` as a top-level JSON field. Additional fields (`uptime`, `timestamp`) are allowed but not required by the minimum spec.
- Rule: The app must export `module.exports = app;` (already present on main) and guard `app.listen` behind `if (require.main === module)` so supertest can require the module without binding a port.

### Test Environment JWT Guard
- Rule: app.js calls `process.exit(1)` when `process.env.JWT_SECRET` is falsy (lines 14-17). Any test that requires `../app` must run after `process.env.JWT_SECRET` is set. The existing `test/jest-setup.js` handles this by setting `process.env.JWT_SECRET = process.env.JWT_SECRET || 'your-secret-key-change-in-production'` before test modules load. The Jest config must reference this file via `--setupFiles ./test/jest-setup.js`.

## Required Code Changes

### 1. Express Route (app.js)
**Files:** `app.js`
**What:** Add a GET /health route handler immediately before the 404 catch-all middleware. The handler needs no database access and no auth middleware.

**Before (key section — lines 421-437 of app.js on main):**
```javascript
app.post('/logout', (req, res) => {
    res.clearCookie('token');
    res.redirect('/');
});

// Health / liveness endpoint — unauthenticated, DB-independent.
app.get('/health', (req, res) => {
    res.status(200).json({
        status: 'ok',
        uptime: process.uptime(),
        timestamp: new Date().toISOString()
    });
});

// Error handling middleware
app.use((req, res) => {
    res.status(404).render('404');
});
```

**After (minimal compliant form — uptime/timestamp are optional; status: 'ok' is mandatory):**
```javascript
app.post('/logout', (req, res) => {
    res.clearCookie('token');
    res.redirect('/');
});

// Health / liveness endpoint — unauthenticated, DB-independent.
app.get('/health', (req, res) => {
    res.status(200).json({ status: 'ok' });
});

// Error handling middleware
app.use((req, res) => {
    res.status(404).render('404');
});
```

## Test Cases

### Functional (TC-F-XXX)
- **TC-F-001** Status 200: No setup required → `request(app).get('/health')` → `response.status === 200`
- **TC-F-002** JSON content type: No setup required → `request(app).get('/health')` → `response.headers['content-type']` matches `/application\/json/`
- **TC-F-003** Body status field: No setup required → `request(app).get('/health')` → `response.body.status === 'ok'`
- **TC-F-004** No auth cookie emitted: No setup required → `request(app).get('/health')` → no `set-cookie` header with `token=` prefix
- **TC-F-005** Unauthenticated access: Send GET /health with no cookie and no Authorization header → response.status is 200, not 302 and not 401

### Edge Cases (TC-E-XXX)
- **TC-E-001** Unsupported method: `request(app).post('/health')` → `response.status === 404` (catch-all fires)
- **TC-E-002** Sub-path: `request(app).get('/health/deep')` → `response.status === 404` (no sub-routes registered)
- **TC-E-003** Missing JWT_SECRET in test: If `process.env.JWT_SECRET` is not set before `require('../app')` runs, `process.exit(1)` is called and the test process terminates — ensure jest-setup.js runs first via `--setupFiles` flag

### Regression (TC-R-XXX)
- **TC-R-001** Homepage unaffected: GET / still returns 200 and renders the index view after /health route is inserted
- **TC-R-002** Login redirect: GET /dashboard with no cookie still returns 302 to /login after /health route is inserted
- **TC-R-003** 404 catch-all: GET /nonexistent-path still returns 404 after /health is registered before the catch-all
