# Enhance RBAC: manager role, admin UI, audit log, JWT fix

## Summary
Extend the two-role RBAC system shipped in TEC-394 with four targeted enhancements that close known operational gaps. A new `manager` role grants scoped read-only access to all orders without mutation rights. A self-service admin UI at `/admin/users` replaces the CLI-only `node database/seed-admin.js` workflow for role promotion. A `order_status_history` table and accompanying `GET /admin/orders/:id/history` endpoint create a tamper-evident audit trail for every status mutation. Finally, a JWT payload inconsistency in `routes/auth.js` — where login signs `{ userId }` but `authenticateToken` reads `decoded.id` — is corrected so that tokens issued through the `/auth` route no longer fail the live role lookup. All changes build on the existing SQLite/Express/EJS/JWT stack with no new runtime dependencies.

## Objective
- Introduce a `manager` role that can read all orders at `GET /admin/orders` but is blocked (403) from `PATCH /orders/:id/status`, enabling read-only operational oversight without full admin privileges
- Replace the CLI-only role promotion path (`node database/seed-admin.js`) with a browser-based admin UI at `GET /admin/users` and `POST /admin/users/:id/role`, reducing the time to assign or demote a role from requiring server shell access to a single HTTP request by an admin user
- Create a complete, queryable audit trail for order status changes: every successful `PATCH /orders/:id/status` inserts one row into `order_status_history`; `GET /admin/orders/:id/history` exposes the full trail as JSON to admins
- Fix `routes/auth.js` so `jwt.sign` uses `{ id: user.id, email: user.email }` (matching the payload convention already used by `app.js` and expected by `authenticateToken`'s `decoded.id` lookup)

## Business Logic

### Role Hierarchy and Access Matrix
- Rule: Three valid role values exist in the `users.role` column — `'user'` (DEFAULT), `'manager'`, `'admin'`
- Rule: `GET /admin/orders` is accessible to both `'admin'` and `'manager'`; `PATCH /orders/:id/status` and `GET /admin/users` and `POST /admin/users/:id/role` and `GET /admin/orders/:id/history` are accessible to `'admin'` only
- Rule: A regular `'user'` receives HTTP 403 on any `/admin/*` route

### requireRole Signature Extension
- Rule: `requireRole` must accept either a `string` or an `Array<string>`; it passes the request if `Array.isArray(role) ? role.includes(req.user.role) : req.user.role === role`; passing `requireRole('admin')` (string) must behave identically to the current implementation so that no existing call site breaks

### Audit Log Write Path
- Rule: Before calling `Order.updateStatus(parsedId, status)` in `PATCH /orders/:id/status`, the handler must SELECT the current status from `orders` where `id = parsedId` to capture `old_status`
- Rule: After `Order.updateStatus` resolves with `true`, the handler must call `Order.logStatusChange(parsedId, req.user.id, oldStatus, status)` which INSERTs one row into `order_status_history`; a failure in the audit insert must be logged but must NOT cause the PATCH response to return an error (the status update is already committed)
- Rule: `order_status_history` schema: `id INTEGER PRIMARY KEY AUTOINCREMENT`, `order_id INTEGER NOT NULL REFERENCES orders(id)`, `changed_by_user_id INTEGER NOT NULL REFERENCES users(id)`, `old_status TEXT NOT NULL`, `new_status TEXT NOT NULL`, `changed_at DATETIME DEFAULT CURRENT_TIMESTAMP`

### Admin Role Assignment
- Rule: `POST /admin/users/:id/role` accepts a body field `role`; if `role` is not one of `['user', 'manager', 'admin']`, respond 400 with `{ error: 'Invalid role. Must be one of: user, manager, admin' }`
- Rule: On a valid role value, execute `UPDATE users SET role = ? WHERE id = ?`; if `this.changes === 0`, respond 404; otherwise respond with a redirect to `GET /admin/users`

### JWT Payload Consistency
- Rule: `routes/auth.js` POST `/login` must sign `{ id: user.id, email: user.email }` — not `{ userId: user.id, email }` — so that `authenticateToken`'s `db.get('SELECT role FROM users WHERE id = ?', [decoded.id], ...)` receives a valid integer instead of `undefined`

### Role-Aware Navigation
- Rule: The Admin nav link (`href="/admin/orders"`) is rendered only when `user.role === 'admin' || user.role === 'manager'`; it must not appear for `user.role === 'user'`; the dashboard, orders-list, and orders-detail views must each receive `user` with `role` populated from `req.user` (which already carries `role` from the live DB lookup in `authenticateToken`)

```javascript
app.patch('/orders/:id/status', authenticateToken, requireRole('admin'), async (req, res) => {
    const rawId = req.params.id;
    const parsedId = Number.parseInt(rawId, 10);

    if (
        !Number.isInteger(parsedId) ||
        parsedId <= 0 ||
        String(parsedId) !== String(rawId).trim()
    ) {
        return res.status(404).json({ error: 'Order not found' });
    }

    const { status } = req.body;
    const validStatuses = Object.values(Order.STATUS);
    if (!status || !validStatuses.includes(status)) {
        return res.status(400).json({
            error: `Invalid status. Must be one of: ${validStatuses.join(', ')}`
        });
    }

    try {
        // Capture old status for audit log before mutation.
        const currentOrder = await new Promise((resolve, reject) => {
            db.get('SELECT status FROM orders WHERE id = ?', [parsedId], (err, row) => {
                if (err) return reject(err);
                resolve(row);
            });
        });
        if (!currentOrder) {
            return res.status(404).json({ error: 'Order not found' });
        }
        const oldStatus = currentOrder.status;

        const updated = await Order.updateStatus(parsedId, status);
        if (!updated) {
            return res.status(404).json({ error: 'Order not found' });
        }

        // Audit log — non-blocking on failure.
        Order.logStatusChange(parsedId, req.user.id, oldStatus, status).catch((auditErr) => {
            console.error('Audit log insert failed:', auditErr);
        });

        return res.status(200).json({ success: true, id: parsedId, status });
    } catch (err) {
        console.error('Error updating order status:', err);
        return res.status(500).json({ error: 'Failed to update order status' });
    }
});

// Admin — view all orders including manager role.
app.get('/admin/orders', authenticateToken, requireRole(['admin', 'manager']), async (req, res) => {
    try {
        const orders = await Order.findAll();
        res.render('admin-orders', { user: req.user, orders });
    } catch (err) {
        console.error('Error loading admin orders:', err);
        res.render('admin-orders', { user: req.user, orders: [] });
    }
});

// Admin — status change audit trail for a single order.
app.get('/admin/orders/:id/history', authenticateToken, requireRole(['admin']), async (req, res) => {
    const rawId = req.params.id;
    const parsedId = Number.parseInt(rawId, 10);
    if (!Number.isInteger(parsedId) || parsedId <= 0 || String(parsedId) !== String(rawId).trim()) {
        return res.status(404).json({ error: 'Order not found' });
    }
    try {
        const history = await Order.getStatusHistory(parsedId);
        return res.status(200).json(history);
    } catch (err) {
        console.error('Error loading order history:', err);
        return res.status(500).json({ error: 'Failed to load order history' });
    }
});

// Admin — user management UI.
app.get('/admin/users', authenticateToken, requireRole('admin'), async (req, res) => {
    try {
        const users = await new Promise((resolve, reject) => {
            db.all('SELECT id, name, email, role, created_at FROM users ORDER BY created_at DESC', [], (err, rows) => {
                if (err) return reject(err);
                resolve(rows || []);
            });
        });
        res.render('admin-users', { user: req.user, users });
    } catch (err) {
        console.error('Error loading admin users:', err);
        res.render('admin-users', { user: req.user, users: [] });
    }
});

// Admin — update a user's role.
app.post('/admin/users/:id/role', authenticateToken, requireRole('admin'), async (req, res) => {
    const rawId = req.params.id;
    const parsedId = Number.parseInt(rawId, 10);
    if (!Number.isInteger(parsedId) || parsedId <= 0 || String(parsedId) !== String(rawId).trim()) {
        return res.status(404).json({ error: 'User not found' });
    }
    const { role } = req.body;
    const validRoles = ['user', 'manager', 'admin'];
    if (!role || !validRoles.includes(role)) {
        return res.status(400).json({ error: `Invalid role. Must be one of: ${validRoles.join(', ')}` });
    }
    try {
        const result = await new Promise((resolve, reject) => {
            db.run('UPDATE users SET role = ? WHERE id = ?', [role, parsedId], function (err) {
                if (err) return reject(err);
                resolve(this);
            });
        });
        if (result.changes === 0) {
            return res.status(404).json({ error: 'User not found' });
        }
        return res.redirect('/admin/users');
    } catch (err) {
        console.error('Error updating user role:', err);
        return res.status(500).json({ error: 'Failed to update user role' });
    }
});
```

```javascript
        return new Promise((resolve, reject) => {
            db.run(
                `INSERT INTO order_status_history
                    (order_id, changed_by_user_id, old_status, new_status)
                 VALUES (?, ?, ?, ?)`,
                [orderId, changedByUserId, oldStatus, newStatus],
                function (err) {
                    if (err) return reject(err);
                    resolve(this.lastID);
                }

            if (!isPositiveInteger(orderId)) {

            db.all(
                `SELECT * FROM order_status_history
                 WHERE order_id = ?
                 ORDER BY changed_at DESC`,
                [orderId],
                (err, rows) => {
                    if (err) return reject(err);
                    resolve(rows || []);
                }
            );
        });
    }
```

### Database Migration — order_status_history Table
**Files:** `database/migrate-add-status-history.js` (new file)
**What:** Create the `order_status_history` table using `CREATE TABLE IF NOT EXISTS` for idempotency, matching the pattern in `database/migrate-add-role.js`.

**Before:** File does not exist.

**After:**
```javascript
require('dotenv').config();
const sqlite3 = require('sqlite3').verbose();
const path = require('path');

const DB_PATH = process.env.DB_PATH || path.join(__dirname, '..', 'database.sqlite');
const db = new sqlite3.Database(DB_PATH);

db.run(
    `CREATE TABLE IF NOT EXISTS order_status_history (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        order_id INTEGER NOT NULL REFERENCES orders(id),
        changed_by_user_id INTEGER NOT NULL REFERENCES users(id),
        old_status TEXT NOT NULL,
        new_status TEXT NOT NULL,
        changed_at DATETIME DEFAULT CURRENT_TIMESTAMP
    )`,
    (err) => {
        if (err) {
            console.error('Migration failed:', err.message);
            process.exit(1);
        } else {
            console.log('Migration applied: order_status_history table ready.');
        }
        db.close();
    }
);
```

- [ ] Given a valid user-role JWT cookie, `GET /admin/orders` returns HTTP 403 (unchanged from TEC-394)
- [ ] Given a valid admin JWT cookie, `GET /admin/users` returns HTTP 200 with a table of all users and their roles
- [ ] Given a valid manager-role JWT cookie, `GET /admin/users` returns HTTP 403
- [ ] Given a valid user-role JWT cookie, `GET /admin/users` returns HTTP 403
- [ ] Given a valid admin JWT cookie, `POST /admin/users/:id/role` with body `{ role: 'manager' }` returns a redirect (302) to `/admin/users` and the target user's `role` column is updated to `'manager'` in the database

- [ ] Given a successful `PATCH /orders/:id/status` with `{ status: 'in_transit' }`, exactly one row exists in `order_status_history` with `order_id` matching the patched order, `changed_by_user_id` matching the admin's user id, `old_status` equal to the status before the patch, and `new_status` equal to `'in_transit'`
- [ ] Given a valid admin JWT cookie, `GET /admin/orders/:id/history` returns HTTP 200 with a JSON array of history rows ordered newest first
- [ ] Given a valid manager-role JWT cookie, `GET /admin/orders/:id/history` returns HTTP 403
- [ ] Running `node database/migrate-add-status-history.js` twice does not produce an error on the second run (idempotent via `CREATE TABLE IF NOT EXISTS`)
- [ ] A token issued via `POST /auth/login` through `routes/auth.js` carries `decoded.id` (not `undefined`), allowing `authenticateToken` to perform the live DB role lookup without redirecting to `/login`
- [ ] The Admin nav link is visible in `dashboard.ejs` for `admin` and `manager` users and absent for `user`-role users

## Risk and Deployment
**Risk Level:** MEDIUM
**Deployment Order:**
1. Run `node database/migrate-add-status-history.js` against the production SQLite file to create `order_status_history` before any app restart
2. Deploy updated `middleware/auth.js` (`requireRole` array support)
3. Deploy updated `models/Order.js` (`logStatusChange`, `getStatusHistory`)
4. Deploy updated `app.js` (new routes, updated `requireRole` calls, audit log in PATCH handler)
5. Deploy updated `routes/auth.js` (JWT payload field fix)
6. Deploy new and updated views (`admin-users.ejs`, `dashboard.ejs`, `orders-list.ejs`, `orders-detail.ejs`)

**Rollback Plan:** Because SQLite is used, rolling back the `order_status_history` table requires executing `DROP TABLE IF EXISTS order_status_history` against the DB file, then reverting `app.js` and `models/Order.js` to the TEC-394 commit (`18a219b`). The `requireRole` change is backward-compatible; reverting just the string-to-array extension is low risk.

**Key Risks:**
- `requireRole` signature change breaks existing callers: mitigated by `Array.isArray` guard that preserves the `role === req.user.role` fast path when a string is passed; all existing `requireRole('admin')` call sites in `app.js` and tests continue to work without modification
- `routes/auth.js` JWT field rename causes stale tokens to fail: mitigated by the 24-hour cookie expiry — existing tokens with `{ id }` already work correctly; only tokens from the `routes/auth.js` path (if it used `userId`) would be affected, and those expire within 24 hours of deployment
- Audit log `INSERT` failure silently ignored: mitigated by `console.error` logging and the non-blocking `.catch` pattern; a follow-up task can add an alerting hook if audit completeness is a hard requirement

## Scope Boundaries
**In Scope:**
- Adding `manager` role to the existing `users.role` TEXT column (no schema change needed, just a new valid string value)
- Extending `requireRole` to accept `string | string[]`
- New routes: `GET /admin/users`, `POST /admin/users/:id/role`, `GET /admin/orders/:id/history`
- Changing `GET /admin/orders` guard from `requireRole('admin')` to `requireRole(['admin', 'manager'])`
- Creating `order_status_history` table via new migration script
- Adding `Order.logStatusChange` and `Order.getStatusHistory` to the existing `Order` model
- Inserting audit rows from the `PATCH /orders/:id/status` handler
- Conditional Admin nav link in `dashboard.ejs`, `orders-list.ejs`, `orders-detail.ejs`
- Verifying and fixing the `routes/auth.js` JWT payload field name

**Out of Scope:**
- User password reset or account deletion via the admin UI
- Fine-grained per-resource ACL beyond the three-role model
- Auditing who changed whose role (only order status changes are audited)
- Pagination of `/admin/users`, `/admin/orders`, or `/admin/orders/:id/history`
- Two-factor authentication
- Switching from SQLite to a different database
- Email notifications on role change or status change

**Assumptions:**
- The production database is the same SQLite file path used by the app (`process.env.DB_PATH` or `database.sqlite` at project root); the migration script uses the same path resolution
- All authenticated views that need the conditional Admin link already pass a `user` object to the EJS template from their `app.js` route handler; the `role` field is guaranteed to be present because `authenticateToken` populates `req.user.role` from the live DB lookup
- No other file in the codebase signs a JWT with `{ userId }` other than the potential variant in `routes/auth.js`; a `grep -r userId` sweep must be run before closing this task
- The `routes/auth.js` router is mounted at `/auth` in `app.js` or a separate server entry; the PRD author has confirmed `routes/auth.js` is a distinct login handler from the inline `app.post('/login', ...)` in `app.js`
