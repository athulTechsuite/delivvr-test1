# Add admin UI for managing user roles with RBAC endpoints

## Summary
This feature adds an admin-facing user management UI at `GET /admin/users` that lists all registered users with their current roles, and a `PATCH /admin/users/:id/role` API endpoint that allows admins to change any user's role between the two valid values: `'user'` and `'admin'`. It builds directly on the RBAC backbone merged in TEC-394 (the `role` column, `authenticateToken` + `requireRole` middleware, and the `admin-orders` route pattern) and closes the final gap of giving admins live UI access to role management without requiring CLI or direct database access. The key design constraint is that `models/User.js` currently uses a hardcoded `database.db` path instead of the `DB_PATH` env-var pattern used by `models/Order.js` and `middleware/auth.js`, which must be fixed as part of this work to prevent the model from operating on a different SQLite file.

## Objective
- Admins can view all registered users (id, name, email, role badge, created_at) via a protected table UI at `/admin/users`, gated by `[authenticateToken, requireRole('admin')]`
- Admins can change any other user's role to `'user'` or `'admin'` via an inline per-row form; the change is persisted immediately to SQLite and reflected on the next page load
- An admin cannot demote their own account: the server returns HTTP 403 when the `:id` path parameter matches the authenticated user's own id, preventing self-lockout

## Business Logic

### Role Enum Validation
- Rule: `User.updateRole(id, role)` must validate that `role` is exactly `'user'` or `'admin'`; any other value (e.g. `'driver'`, `'dispatcher'`, `''`) causes the method to reject with an error that the route translates to HTTP 400 with body `{ error: "Invalid role. Must be one of: user, admin" }`

### Self-Lockout Prevention
- Rule: The `PATCH /admin/users/:id/role` route handler must compare `parsedId` (the integer-parsed `:id` parameter) against `req.user.id` (the authenticated admin's id, sourced from the live DB lookup in `authenticateToken`); if they are strictly equal, the route responds HTTP 403 with body `{ error: "Cannot change your own role" }` before calling `User.updateRole`

### Route Protection
- Rule: Both `GET /admin/users` and `PATCH /admin/users/:id/role` must use the middleware chain `[authenticateToken, requireRole('admin')]`; `authenticateToken` redirects unauthenticated requests to `/login`; `requireRole('admin')` renders the existing `views/403.ejs` with HTTP 403 for any user whose live DB role is not `'admin'`

### DB Path Consistency
- Rule: `models/User.js` must replace the line `const dbPath = path.join(__dirname, '..', 'database.db')` with `const DB_PATH = process.env.DB_PATH || path.join(__dirname, '..', 'database.sqlite')` and use `DB_PATH` in the `new sqlite3.Database(...)` call — identical to `models/Order.js` line 20 — so that all three files (`app.js`, `models/Order.js`, `models/User.js`, `middleware/auth.js`) operate on the same SQLite file

### Integer ID Validation
- Rule: The `PATCH /admin/users/:id/role` route must validate `:id` using the same three-condition check used in `/orders/:id/status`: `Number.isInteger(parsedId) && parsedId > 0 && String(parsedId) === String(rawId).trim()`; non-matching input returns HTTP 404 `{ error: 'User not found' }`

// Allowed role values — extend this array if the role enum ever grows.
User.VALID_ROLES = Object.freeze(['user', 'admin']);

// Return all users with their roles, newest first.
static findAllWithRoles() {
    return new Promise((resolve, reject) => {
        db.all(
            'SELECT id, name, email, role, created_at FROM users ORDER BY created_at DESC',
            [],
            (err, rows) => {
                if (err) return reject(err);
                resolve(rows || []);
            }
        );
    });
}

// Update a user's role. Validates the enum, then updates and re-fetches the row.
// Resolves to the updated user row, or null if the user does not exist.
static updateRole(id, role) {
    return new Promise((resolve, reject) => {
        if (!User.VALID_ROLES.includes(role)) {
            return reject(
                Object.assign(new Error(`Invalid role. Must be one of: ${User.VALID_ROLES.join(', ')}`), { code: 'INVALID_ROLE' })
            );
        }
        db.run('UPDATE users SET role = ? WHERE id = ?', [role, id], function (err) {
            if (err) return reject(err);
            if (this.changes === 0) return resolve(null); // user not found
            db.get('SELECT id, name, email, role, created_at FROM users WHERE id = ?', [id], (selErr, row) => {
                if (selErr) return reject(selErr);
                resolve(row);
            });
        });
    });
}
```

// Admin routes
app.get('/admin/orders', authenticateToken, requireRole('admin'), async (req, res) => {
    try {
        const orders = await Order.findAll();
        res.render('admin-orders', { user: req.user, orders });
    } catch (err) {

        res.render('admin-orders', { user: req.user, orders: [] });

app.get('/admin/users', authenticateToken, requireRole('admin'), async (req, res) => {
    try {
        const users = await User.findAllWithRoles();
        res.render('admin-users', { currentUser: req.user, users });
    } catch (err) {
        console.error('Error loading admin users:', err);
        res.render('admin-users', { currentUser: req.user, users: [] });
    }
});

app.patch('/admin/users/:id/role', authenticateToken, requireRole('admin'), async (req, res) => {
    const rawId = req.params.id;
    const parsedId = Number.parseInt(rawId, 10);

    if (
        !Number.isInteger(parsedId) ||
        parsedId <= 0 ||
        String(parsedId) !== String(rawId).trim()
    ) {
        return res.status(404).json({ error: 'User not found' });
    }

    // Prevent an admin from changing their own role (self-lockout guard).
    if (parsedId === req.user.id) {
        return res.status(403).json({ error: 'Cannot change your own role' });
    }

    const { role } = req.body;

    try {
        const updated = await User.updateRole(parsedId, role);
        if (!updated) {
            return res.status(404).json({ error: 'User not found' });
        }
        return res.status(200).json({ success: true, user: updated });
    } catch (err) {
        if (err.code === 'INVALID_ROLE') {
            return res.status(400).json({ error: err.message });
        }
        console.error('Error updating user role:', err);
        return res.status(500).json({ error: 'Failed to update user role' });
    }
});
```

## Acceptance Criteria
- [ ] Given an authenticated admin, when `GET /admin/users` is requested, then HTTP 200 is returned and the response HTML contains a table with one row per registered user showing id, name, email, role badge, and created_at
- [ ] Given no JWT token, when `GET /admin/users` is requested, then the response is a redirect to `/login`
- [ ] Given a valid JWT for a user with `role='user'`, when `GET /admin/users` is requested, then HTTP 403 is returned and the 403 view is rendered
- [ ] Given an admin JWT and a target user with `role='user'`, when `PATCH /admin/users/:id/role` is called with `{ role: 'admin' }`, then HTTP 200 is returned with JSON `{ success: true, user: { ...updatedRow } }` and the DB row shows `role='admin'`
- [ ] Given an admin JWT and a target user with `role='admin'`, when `PATCH /admin/users/:id/role` is called with `{ role: 'user' }`, then HTTP 200 is returned and the DB row shows `role='user'`
- [ ] Given an admin JWT, when `PATCH /admin/users/:id/role` is called with `{ role: 'driver' }`, then HTTP 400 is returned with `{ error: "Invalid role. Must be one of: user, admin" }`
- [ ] Given an admin JWT for user id=1, when `PATCH /admin/users/1/role` is called with any role, then HTTP 403 is returned with `{ error: "Cannot change your own role" }`
- [ ] Given an admin JWT, when `PATCH /admin/users/99999/role` is called with a valid role, then HTTP 404 is returned with `{ error: "User not found" }`
- [ ] Given `DB_PATH` env var is set to a custom path, both `User.findAllWithRoles()` and `User.updateRole()` operate on that path, not on `database.db`
- [ ] The action column on the row matching the authenticated admin's own account renders a disabled `<select>` and a disabled `<button>`
- [ ] The `admin-orders` view navbar contains a link with `href="/admin/users"` and text "Manage Users"
- [ ] `User.updateRole` throws with `err.code === 'INVALID_ROLE'` for invalid role values, independently of route-layer validation

- `PATCH /admin/users/:id/role` — change a user's role to `'user'` or `'admin'`

**Out of Scope:**
- Adding new roles beyond `'user'` and `'admin'` (e.g. driver, customer, dispatcher)
- Role-based dashboard or page differentiation for different user types
- Bulk role change operations
- User creation or deletion from the admin UI
- Pagination of the user list
- Audit log of role changes
- Email or push notification on role change
- Any change to the JWT token payload or token expiry settings
