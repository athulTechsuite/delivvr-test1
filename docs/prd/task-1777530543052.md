# Add role-based access control (RBAC) to delivery management app

## Summary

This feature adds a two-role RBAC system (`customer` / `admin`) to the Delivvr Node.js/Express/SQLite application. A `role` column is added to the `users` table with a safe `ALTER TABLE` migration, the JWT payload is extended to carry that role, and a new `requireRole(role)` middleware in `middleware/auth.js` enforces it at the route level. The critical design constraint is that `app.js` currently defines its own inline `authenticateToken` that diverges from the one in `middleware/auth.js` — both must be unified so a single source of truth protects all routes. The deliverable includes a `GET /admin` dashboard view listing all orders across every user, and a `scripts/seed-admin.js` bootstrap script that promotes or creates an admin account using environment variables.

## Objective

- Gate `GET /admin` so that requests with no token receive HTTP 401 and requests with a valid customer-role JWT receive HTTP 403, while valid admin JWTs render the full all-orders dashboard
- Extend the JWT payload issued at `POST /login` to include a `role` field, ensuring every existing session mechanism continues working unchanged
- Provide `scripts/seed-admin.js` so that the first admin can be bootstrapped from the command line using `ADMIN_EMAIL` and `ADMIN_PASSWORD` env vars without requiring any UI or direct DB client access

## Mandatory Codebase Review

- **`app.js`** — The main entry point. Contains the inline `authenticateToken` (lines 66–80) that reads from `req.cookies.token` only (unlike the file in `middleware/auth.js`). Also contains the `db.serialize()` block (lines 25–45) where the schema migration must be inserted, and the `jwt.sign` call at line 285 that must gain a `role` field.
- **`middleware/auth.js`** — Contains the canonical `authenticateToken` (reads both `Authorization` header and cookie) plus `redirectIfAuthenticated`. The new `requireRole(role)` middleware goes here. The inline version in `app.js` must be replaced with an import from this file.
- **`models/Order.js`** — Uses `process.env.DB_PATH || path.join(__dirname, '..', 'database.sqlite')` (line 20) — the same path as `app.js`. A new static `Order.findAll()` method is added here following the same Promise + `db.all()` pattern used by `Order.findByUserId()`.
- **`views/dashboard.ejs`** — Reference template showing the full standalone HTML pattern (no `layout.ejs` include) used by all views. `admin-dashboard.ejs` must follow the same navbar, Material Design class system, and Bootstrap Icons conventions.
- **`models/User.js`** — Points at a **different** DB file (`database.db`, line 6) and is **not** used by `app.js`. The seed script must use `DB_PATH` env var or `database.sqlite` directly, never import this model.

## Business Logic

### Role Model
- Rule: Two roles exist — `customer` (default) and `admin`. No other values are valid.
- Rule: Every new signup via `POST /signup` receives `role='customer'`; the INSERT must explicitly pass the value even though the column has a DEFAULT, to make intent clear.
- Rule: Role elevation to `admin` is only possible via `scripts/seed-admin.js` or a direct DB UPDATE. There is no self-service or UI-based elevation path.

### JWT Token Contents
- Rule: The `jwt.sign` call at `POST /login` must include `{ id: user.id, email: user.email, role: user.role }`. Tokens issued before this change will not carry `role` and will fail the `requireRole` check — existing sessions must be cleared on deploy.
- Rule: JWT expiry remains `24h` and cookie `maxAge` remains `24 * 60 * 60 * 1000` ms (unchanged).

### Route Authorization
- Rule: `GET /admin` is protected by two sequential middleware: `authenticateToken` (redirects to `/login` on missing/invalid token) then `requireRole('admin')` (returns HTTP 403 JSON `{ error: 'Forbidden' }` when role doesn't match).
- Rule: All existing customer routes (`/dashboard`, `/profile`, `/orders`, `/orders/new`, `/orders/:id`) require only `authenticateToken` and are **not** modified.
- Rule: `requireRole` must call `next()` when `req.user.role === role`, and respond `res.status(403).json({ error: 'Forbidden' })` otherwise.

### Database Migration
- Rule: `ALTER TABLE users ADD COLUMN role TEXT NOT NULL DEFAULT 'customer'` must be wrapped in a try/catch (using `db.run` with an error callback that silences `duplicate column name` errors) so the migration is idempotent on existing databases.
- Rule: Existing rows automatically receive `role='customer'` via the column DEFAULT — no back-fill UPDATE is required.

### Admin Seed Script
- Rule: `scripts/seed-admin.js` reads `ADMIN_EMAIL` and `ADMIN_PASSWORD` from `process.env`; if either is missing it prints an error and exits with code 1.
- Rule: Password is hashed with `bcrypt` at `saltRounds=10` (matching `POST /signup` in `app.js`).
- Rule: Script uses `INSERT OR REPLACE` (SQLite upsert) so running it twice against the same email promotes an existing customer without creating a duplicate row.

/**
 * requireRole(role) — call after authenticateToken.
 * Returns 403 JSON if req.user.role does not match the required role.

const requireRole = (role) => (req, res, next) => {
    if (!req.user || req.user.role !== role) {
        return res.status(403).json({ error: 'Forbidden' });
    }
    next();
};

                 JOIN users u ON u.id = o.user_id

                (err, rows) => {
                    if (err) {
                        return reject(err);
                    }
                    resolve(rows || []);

### 8. Admin Seed Script

**Files:** `scripts/seed-admin.js` *(new file)*

**What:** Standalone Node.js script that creates or promotes an admin user. Uses `INSERT OR REPLACE` for idempotency. Reads the same `DB_PATH` env var as `app.js` and `models/Order.js`.

**After (complete new file):**
```javascript
require('dotenv').config();
const sqlite3 = require('sqlite3').verbose();
const bcrypt = require('bcrypt');
const path = require('path');

const ADMIN_EMAIL = process.env.ADMIN_EMAIL;
const ADMIN_PASSWORD = process.env.ADMIN_PASSWORD;

if (!ADMIN_EMAIL || !ADMIN_PASSWORD) {
    console.error('ERROR: ADMIN_EMAIL and ADMIN_PASSWORD environment variables are required.');
    process.exit(1);
}

const DB_PATH = process.env.DB_PATH || path.join(__dirname, '..', 'database.sqlite');
const db = new sqlite3.Database(DB_PATH, (err) => {
    if (err) {
        console.error('Failed to connect to database:', err.message);
        process.exit(1);
    }
});

const SALT_ROUNDS = 10;

(async () => {
    try {
        const hashedPassword = await bcrypt.hash(ADMIN_PASSWORD, SALT_ROUNDS);

        db.serialize(() => {
            // Ensure role column exists before upserting
            db.run(
                `ALTER TABLE users ADD COLUMN role TEXT NOT NULL DEFAULT 'customer'`,
                (err) => {
                    if (err && !err.message.includes('duplicate column name')) {
                        console.error('Migration warning:', err.message);
                    }
                }
            );

            db.run(
                `INSERT INTO users (name, email, password, role)
                 VALUES ('Admin', ?, ?, 'admin')
                 ON CONFLICT(email) DO UPDATE SET
                     password = excluded.password,
                     role     = 'admin'`,
                [ADMIN_EMAIL, hashedPassword],
                function (err) {
                    if (err) {
                        console.error('Failed to upsert admin user:', err.message);
                        db.close();
                        process.exit(1);
                    }
                    console.log(`Admin user seeded successfully: ${ADMIN_EMAIL}`);
                    db.close();
                }
            );
        });
    } catch (err) {
        console.error('Unexpected error:', err.message);
        db.close();
        process.exit(1);
    }
})();
```

- [ ] `GET /orders/:id` for an order belonging to a different user still returns HTTP 404 (tenant isolation unchanged)
- [ ] Running `ADMIN_EMAIL=admin@test.com ADMIN_PASSWORD=Secret1 node scripts/seed-admin.js` inserts a user with `role='admin'` in `database.sqlite`

- [ ] Running the seed script with missing `ADMIN_EMAIL` exits with code 1 and prints an error message
- [ ] The `/health` endpoint continues to return HTTP 200 JSON with no authentication required
- [ ] The `middleware/auth.js` file exports `authenticateToken`, `redirectIfAuthenticated`, and `requireRole`; `app.js` no longer defines its own inline `authenticateToken`

## Scope Boundaries

**In Scope:**
- Add `role TEXT NOT NULL DEFAULT 'customer'` column to `users` table via idempotent `ALTER TABLE` in `app.js`
- Embed `role` in JWT payload at `POST /login`
- Explicit `role='customer'` in `POST /signup` INSERT
- `requireRole(role)` middleware added to `middleware/auth.js` and exported
- Replace inline `authenticateToken` in `app.js` with import from `middleware/auth.js`
- `GET /admin` route protected by `authenticateToken` + `requireRole('admin')`
- `Order.findAll()` static method returning all orders joined with user info
- `views/admin-dashboard.ejs` — server-rendered EJS table view
- `scripts/seed-admin.js` — admin bootstrap script using `ADMIN_EMAIL` / `ADMIN_PASSWORD` env vars

**Out of Scope:**
- Driver role (not requested)
- Role-assignment UI — no web form or API endpoint for changing a user's role
- User management panel beyond the all-orders table
- Fine-grained per-resource permissions (e.g., read-only admin vs. write admin)
- Pagination or search on the admin dashboard
- Email notifications on role change

**Assumptions:**
- `database.sqlite` (not `database.db`) is the canonical database for the running application; `models/User.js` and its `database.db` reference are dead code and must not be used
- `JWT_SECRET` is already set as a required env var (enforced at startup in `app.js` line 14–17) — no change needed
- Existing customer sessions issued before this deploy will work on all customer routes; only `/admin` access requires a re-login to obtain a role-bearing token
- The server environment supports SQLite `ALTER TABLE ... ADD COLUMN` with a DEFAULT value (SQLite ≥ 3.1.3, satisfied by any recent `sqlite3` npm package version)
